# Два скрипта для Claude Code: проверить права токена и убрать старые логи

На Linux файл входа Claude Code может лежать в том же каталоге, что и пользовательские настройки. В тестовом профиле я выставил обоим файлам права 644. Для пустого файла настроек это само по себе мало что говорит, а для файла входа сразу возникает вопрос: зачем группе и остальным пользователям право на чтение?

Чтобы заметить разницу, открывать JSON с токеном не нужно. Я сделал две утилиты: одна проверяет права файлов в Linux, другая показывает, сколько места занимают старые отладочные логи Claude Code, и по отдельной команде удаляет их. Очистка рассчитана на Linux, macOS и Windows. [Код и команды для каждой ОС](https://github.com/stufently/claude-code-config-audit).

## Что хранится в профиле

| Файл | Что в нём | Зачем различать |
| --- | --- | --- |
| `~/.claude/settings.json` | Пользовательские настройки CLI | Могут действовать сразу в нескольких проектах. |
| `.claude/settings.json` и `.claude/settings.local.json` в проекте | Общие и индивидуальные параметры проекта | У двух разработчиков в одном репозитории поведение может различаться. |
| `~/.claude.json` | Сведения об аккаунте, конфигурация MCP и состояние проектов, включая решения о доверии | При удалении можно потерять настройки подключённых инструментов. |
| `~/.claude/.credentials.json` в Linux | Учётные данные для входа | Документированный режим файла — 600. Для проверки достаточно метаданных. |

В таблице указаны стандартные пути. Если задана переменная `CLAUDE_CONFIG_DIR`, скрипты учитывают её при поиске пользовательских настроек, файла входа и логов. Проектные настройки аудит ищет от каталога, в котором его запустили. [Файлы настроек](https://code.claude.com/docs/en/settings) · [Хранение учётных данных по платформам](https://code.claude.com/docs/en/authentication#credential-management).

## Что увидит пользователь Linux

Команды можно скопировать целиком. Откройте терминал в проекте, который хотите проверить. Git скачает утилиту в домашний каталог, а текущим каталогом останется ваш проект.

```bash
git clone https://github.com/stufently/claude-code-config-audit.git "$HOME/claude-code-config-audit"
bash "$HOME/claude-code-config-audit/audit.sh"
```

Вот вывод из контейнера с двумя пустыми файлами. Даже названия проекта и пользователя для него не понадобились.

```text
user-settings: present, mode 644
credentials: present, mode 644 (expected 600)
project-settings: not found
project-local-settings: not found
```

Вторая строка заслуживает внимания. Режим 644 разрешает владельцу чтение и запись, группе и остальным — чтение. Возможность добраться до файла зависит ещё и от прав каталогов и ACL. Когда я изменил режим тестового файла на 600, предупреждение исчезло, код выхода сменился с 1 на 0. Более строгий 400 скрипт тоже отметит: это проверка на расхождение с документированным режимом, а не доказательство утечки.

На macOS данные входа обычно хранятся в связке ключей. Для некоторых способов входа при отказе связки CLI может использовать файл. Windows применяет права доступа профиля пользователя. Поэтому числовую проверку режима имеет смысл запускать именно в Linux. [Как Claude Code управляет учётными данными](https://code.claude.com/docs/en/authentication#credential-management).

## Сколько места можно вернуть

Для очистки я задал узкую область: обычные файлы с именем в формате UUID и расширением .txt непосредственно в каталоге debug. Возраст считается от последнего изменения. Скрипт суммирует размеры по метаданным. Открывать логи и разбирать строки внутри не требуется.

Например, если в каталоге лежат свежий лог, старый лог и файл notes.txt, то при пороге 30 суток в отчёт попадёт только старый лог подходящего формата. Для Linux и macOS после клонирования команда предпросмотра такая:

```bash
bash "$HOME/claude-code-config-audit/clean-logs.sh" --days 30
```

Для Windows после клонирования в ту же папку домашнего каталога:

```powershell
& "$HOME/claude-code-config-audit/clean-logs.ps1" --days 30
```

Обе команды вызывают один скрипт на Python 3. Чтобы удалить найденное, добавьте к своей команде `--apply`. Эту же команду можно запускать по расписанию. Если через сутки повторить очистку, кандидатами станут только файлы, которые к этому времени пересекли возрастной порог.

## Что такая диагностика подтверждает

На диске можно проверить наличие файла, права и занимаемое место. Чтобы утверждать, что определённая версия CLI передаёт локальное поле с каждым запросом модели, нужно отдельное наблюдение сетевого обмена. Здесь такого измерения не было. Если ошибка относится к приостановке аккаунта, её рассматривает поддержка через форму апелляции. [Порядок апелляции](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals).
