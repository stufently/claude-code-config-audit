# Что почистить в Claude Code после того, как вас забанили

Если при входе в Claude появился экран блокировки, чистить компьютер для подачи апелляции не требуется. Сначала откройте этот аккаунт в браузере: на экране ограничения Anthropic показывает доступные действия, включая форму апелляции и, в предусмотренных случаях, экспорт данных. Это стоит сделать до того, как разбирать файлы на диске. [Инструкция Anthropic](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals).

Если задача — закончить работу на этом компьютере, для входа через аккаунт у Claude Code есть штатная команда `/logout` внутри CLI. Если в проекте использовался отдельный API-ключ и он попал в чужие руки, его следует отозвать у провайдера: удаление локальной копии оставляет уже скопированный секрет действительным. [Как Claude Code хранит учётные данные](https://code.claude.com/docs/en/authentication#credential-management).

## Что хранится в профиле

| Файл | Что в нём | Зачем различать |
| --- | --- | --- |
| `~/.claude/settings.json` | Пользовательские настройки CLI | Могут действовать сразу в нескольких проектах. |
| `.claude/settings.json` и `.claude/settings.local.json` в проекте | Общие и индивидуальные параметры проекта | У двух разработчиков в одном репозитории поведение может различаться. |
| `~/.claude.json` | Сведения об аккаунте, конфигурация MCP и состояние проектов, включая решения о доверии | При удалении можно потерять настройки подключённых инструментов. |
| `~/.claude/.credentials.json` в Linux | Учётные данные для входа | Документированный режим файла — 600. Для проверки достаточно метаданных. |

В таблице указаны стандартные пути. Если задана переменная `CLAUDE_CONFIG_DIR`, утилита учитывает её при поиске пользовательских настроек и файла входа. Проектные настройки аудит ищет от каталога, в котором его запустили. [Файлы настроек](https://code.claude.com/docs/en/settings) · [Хранение учётных данных по платформам](https://code.claude.com/docs/en/authentication#credential-management).

## Что увидит пользователь Linux

Команды можно скопировать целиком. Откройте терминал в проекте, который хотите проверить. Git скачает утилиту в домашний каталог, а текущим каталогом останется ваш проект.

```bash
git clone https://github.com/stufently/claude-code-config-audit.git "$HOME/claude-code-config-audit"
bash "$HOME/claude-code-config-audit/audit.sh"
```

Вот вывод из контейнера с двумя пустыми файлами. Даже названия проекта и пользователя для него не понадобились.

```text
user-settings: present, mode 644
credentials: present, mode 644 (expected 600)
project-settings: not found
project-local-settings: not found
```

Вторая строка заслуживает внимания. Режим 644 разрешает владельцу чтение и запись, группе и остальным — чтение. Возможность добраться до файла зависит ещё и от прав каталогов и ACL. Когда я изменил режим тестового файла на 600, предупреждение исчезло, код выхода сменился с 1 на 0. Более строгий 400 скрипт тоже отметит: это проверка на расхождение с документированным режимом, а не доказательство утечки.

На macOS данные входа обычно хранятся в связке ключей. Для некоторых способов входа при отказе связки CLI может использовать файл. Windows применяет права доступа профиля пользователя. Поэтому числовую проверку режима имеет смысл запускать именно в Linux. [Как Claude Code управляет учётными данными](https://code.claude.com/docs/en/authentication#credential-management).

## Что такая диагностика подтверждает

На диске можно проверить наличие файла и его права. Чтобы утверждать, что определённая версия CLI передаёт локальное поле с каждым запросом модели, нужно отдельное наблюдение сетевого обмена. Здесь такого измерения не было. Если ошибка относится к приостановке аккаунта, её рассматривает поддержка через форму апелляции. [Порядок апелляции](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals).
