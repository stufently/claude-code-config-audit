# Инструменты для локального профиля Claude Code

Две задачи: проверить права файла входа в Linux и освободить место, занятое старыми диагностическими логами CLI, в Linux, macOS или Windows.

## Проверить права в Linux

Откройте терминал в каталоге **проекта, который хотите проверить**. Первый раз скачайте утилиты в домашний каталог и запустите аудит, оставаясь в проекте:

```bash
git clone https://github.com/stufently/claude-code-config-audit.git "$HOME/claude-code-config-audit"
bash "$HOME/claude-code-config-audit/audit.sh"
```

При следующем запуске нужна только вторая команда. Требуются Bash и stat с поддержкой `-c %a`. Скрипт проверяет пользовательские настройки и файл входа из каталога конфигурации, а также настройки текущего проекта. Вывод содержит фиксированные названия и права. Пример для тестового профиля:

```text
user-settings: present, mode 644
credentials: present, mode 644 (expected 600)
project-settings: not found
project-local-settings: not found
```

Для файла входа Anthropic указывает режим 600. При 644 биты группы и остальных пользователей разрешают чтение. При 400 файл доступен владельцу только для чтения: скрипт также отметит отличие от 600. Для оценки фактического доступа нужны ещё владелец, права каталогов и ACL. [Документация по хранению учётных данных](https://code.claude.com/docs/en/authentication#credential-management).

Код выхода 0 означает, что проверка завершена без замечаний; необязательные отсутствующие файлы допустимы. Код 1 означает отличие режима, недоступный каталог, неожиданный тип файла или пропущенную символьную ссылку вместо файла. Код 2 — ошибка вызова или платформы.

## Удалить старые диагностические логи

Нужен Python 3 (проверено на Python 3.14). Оба скрипта запускают одну реализацию. По умолчанию она показывает число файлов и их суммарный размер. Удаление включается флагом `--apply`. Используйте в собственном локальном профиле.

**Linux и macOS** — после клонирования командой выше:

```bash
bash "$HOME/claude-code-config-audit/clean-logs.sh" --days 30
bash "$HOME/claude-code-config-audit/clean-logs.sh" --days 30 --apply
```

**Windows, PowerShell** — при первом запуске:

```powershell
git clone https://github.com/stufently/claude-code-config-audit.git "$HOME/claude-code-config-audit"
& "$HOME/claude-code-config-audit/clean-logs.ps1" --days 30
```

Для удаления:

```powershell
& "$HOME/claude-code-config-audit/clean-logs.ps1" --days 30 --apply
```

Если запуск PowerShell-скриптов ограничен, ту же проверку можно вызвать напрямую: `py -3 "$HOME/claude-code-config-audit/clean_logs.py" --days 30`.

Скрипт смотрит только непосредственно в каталог `debug` внутри пользовательского профиля CLI. Учитывает обычные файлы с именем вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx.txt` (шестнадцатеричные цифры), время изменения которых старше указанного числа суток. Файлы других форматов, подкаталоги и ссылки пропускаются. Если каталог профиля либо его предок — ссылка или Windows junction, скрипт остановится. При заданном `CLAUDE_CONFIG_DIR` для очистки нужен абсолютный путь. История разговоров, настройки и данные входа в область очистки не входят. Для периодического запуска в планировщике используйте ту же команду с `--apply` от своего пользователя.
