# Claude Code Config Audit

Как проверить права файла входа Claude Code в Linux, не открывая его в редакторе и не отправляя конфиг в поддержку. Скрипт использует Bash и GNU-совместимый stat. Claude Code для запуска не требуется.

Из каталога проекта выполните:

```bash
bash /путь/к/репозиторию/audit.sh
```

Проверяются пользовательские настройки и файл учётных данных в каталоге конфигурации, а также общие и локальные настройки в текущем каталоге проекта. Поддерживается CLAUDE_CONFIG_DIR. Отчёт содержит фиксированные названия и права Unix. Содержимое файлов, пути, идентификаторы и значения переменных в вывод не попадают. Скрипт работает локально и только читает метаданные.

Пример для тестового профиля:

```text
user-settings: present, mode 644
credentials: present, mode 644 (expected 600)
project-settings: not found or unreachable
project-local-settings: not found or unreachable
```

В этом примере групповые и прочие биты разрешают чтение файла входа. Доступ конкретного пользователя зависит также от прав каталогов и ACL. Ожидаемый режим файла по документации Anthropic — 600. Отсутствие файла само по себе допустимо, например при другом способе авторизации. [Хранение учётных данных](https://code.claude.com/docs/en/authentication).

Коды выхода: 0 — по выполненным проверкам замечаний нет, 1 — требуется разбор строки отчёта, 2 — неверный вызов или неподдерживаемая платформа. Символьная ссылка вместо проверяемого файла помечается отдельно. Проверка не обходит дерево и не оценивает владельца, ACL, содержимое JSON, сетевой обмен или статус аккаунта.
